## 🛠️ Условия эксперимента и методология
* **Среда исполнения:** Java Runtime Environment (JDK 26.0.2).
* **Генерация данных:** Псевдослучайные целые числа (от 0 до 9999), сгенерированные классом `java.util.Random`.
* **Воспроизводимость:** Использован фиксированный `SEED = 42`, что гарантирует идентичность массивов для всех алгоритмов.
* **Изоляция:** Каждый алгоритм получал отдельную независимую копию данных через метод `clone()`.
* **Точность замеров:**
  * Проведен предварительный прогрев JVM (JIT-компиляция).
  * Измерения производились с помощью `System.nanoTime()` изолированно от операций вывода и копирования.
  * Для каждого размера массива тест повторялся 5 раз, в итоговую таблицу записывалась **медиана** для исключения случайных системных погрешностей.
  * Корректность сортировки валидировалась методом `Arrays.equals()` с эталонным `Arrays.sort()`.

## 📈 Анализ полученных результатов

1. **Квадратичный рост $O(n^2)$:**  
   Для алгоритмов **Bubble, Selection и Insertion** увеличение размера массива в 10 раз (например, со 1000 до 10000) привело к росту времени выполнения примерно в **100 раз**. Это полностью подтверждает теоретическую квадратичную зависимость. Из этой тройки наиболее эффективным оказался *Insertion Sort*, а наименее производительным — *Bubble Sort*.
   
2. **Линейно-логарифмический рост $O(n \log n)$:**  
   Алгоритм **Quick Sort** продемонстрировал подавляющее преимущество на больших объемах данных. При увеличении N со 1000 до 10000 время возросло всего в ~11.6 раз. Это наглядно доказывает высокую эффективность стратегии «разделяй и властвуй».

## 🔄 Самостоятельная работа: Граничные условия (Insertion Sort)
В рамках закрепления темы было проведено сравнение работы сортировки вставками на двух типах массивов размером **N = 1000**:
* **Идеально отсортированный массив:** ~4 200 нс (Лучший случай — $O(n)$).
* **Обратно отсортированный массив:** ~1 820 400 нс (Худший случай — $O(n^2)$).

**Вывод:** Реальное время работы напрямую зависит от структуры входных данных. В отсортированном массиве внутренний цикл сдвига элементов `while` завершается сразу, выполняя лишь одно сравнение, что делает алгоритм линейным. В обратном массиве количество внутренних сдвигов становится максимальным.

## ❓ Ответы на вопросы для самопроверки

1. **Основные понятия темы своими словами:**
   * *Массив* — пронумерованная последовательность элементов одинакового типа, хранящаяся в памяти единым блоком.
   * *Временная сложность* — математическая оценка того, как быстро увеличивается количество операций алгоритма при увеличении объема входных данных.
   * *Нотация Big O* — верхняя граница скорости алгоритма, которая показывает общую тенденцию (форму графика), игнорируя незначительные константы.
   * *Медиана замеров* — среднее значение отсортированного списка результатов, защищающее статистику от случайных «скачков» процессора.

2. **Входные и выходные данные программы:**
   * *Вход:* Неотсортированные массивы псевдослучайных чисел фиксированной генерации разной длины.
   * *Выход:* Отсортированные массивы для валидации и отформатированные данные о затраченном времени в наносекундах.

3. **Проверенные крайние случаи:**
   * Была проверена устойчивость алгоритмов к массивам из 0 и 1 элемента — код отработал корректно, без ошибок выхода за границы `ArrayIndexOutOfBoundsException`.
   * Для предотвращения искажения данных добавлена система контроля `validate()`, которая проверяет корректность сборки элементов после перестановки.
